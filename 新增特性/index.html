新增特性：场景生成、路网生成与 CARLA 执行

本次新增三组能力，对应两个目标：提升场景生成效率、基于实采有限数据生成批量合成数据。

1. 功能总览

功能 MCP 工具 说明
场景模板生成 generate_scenario_from_template 按模板批量生成 .xosc，参数区间内随机
列出场景模板 list_scenario_templates 返回 8 个模板及参数说明
场景校验 validate_scenario 结构往返解析 + 语义断言
路网生成 generate_rich_xodr 生成 7 种布局的 .xodr
列出路网布局 list_road_layouts 返回布局名与默认参数
轨迹导入 import_trajectory CSV / FCD / JSON 三种格式
轨迹批量合成 synthesize_trajectory_dataset 增强算子扩增，带 manifest
分布对比 compare_trajectory_distribution KS 距离与 Wasserstein
导出 SUMO 需求 export_sumo_demand .rou.xml
路网进 CARLA run_road_in_carla 加载、布景、截图
场景进 CARLA run_scenario_in_carla 播放 .xosc 并截图
CARLA 状态 list_carla_maps 版本、当前地图、地图列表

2. 环境配置

2.1 软件版本

项目 版本 说明
Python 3.10 CARLA PythonAPI 的 wheel 只提供到 3.10
CARLA 0.9.16 对应 carla==0.9.16
操作系统 Windows 10 / 11 CARLA 服务端只在这里跑
显卡 集显可用 测试在 AMD Radeon 880M 集显 + 低画质下完成

2.2 安装依赖

cd mcp
pip install -r llm/requirements.txt

本次新增的关键依赖：

包 版本 用途
scenariogeneration >=0.16.0 OpenSCENARIO / OpenDRIVE 对象模型
lxml >=5.0.0 XSD 校验
carla 0.9.16 CARLA 客户端

scenariogeneration 在库内是延迟导入的。缺失时不影响 MCP 服务启动， 只有调用场景/路网相关工具时才报错。

2.3 配置 API Key

在项目根目录创建 .env：

DEEPSEEK_API_KEY=sk-xxxxxxxxxxxxxxxx

2.4 启动 CARLA

无界面模式（省显存，适合集显/服务器）：

cd D:\CARLA_0.9.16
CarlaUE4.exe -RenderOffScreen -quality-level=Low -nosound -carla-port=2000

成功标志：进程 CarlaUE4-Win64-Shipping 存在，端口 2000 处于监听状态。

参数说明：

参数 作用
-RenderOffScreen 不弹窗口，离屏渲染（截图仍可用）
-quality-level=Low 降低画质，集显可用
-nosound 关闭音频，减少资源占用
-carla-port=2000 服务端口，默认 2000

2.5 启动 MCP 服务

mcp.bat

或手动：

python llm/main_ai.py

浏览器打开 http://127.0.0.1:3000，页面顶部「场景快捷按钮」面板可以不输入文字直接执行场景。

3. 使用说明与示例

3.1 场景生成

工具参数

generate_scenario_from_template

参数 类型 默认值 说明

n int 1 生成数量
seed int None 随机种子；相同种子结果可复现
out_dir string llm/output/scenarios 输出目录

8 个场景模板

模板 场景含义 实体数

lead_stationary 前车静止 2

对话示例

列出所有可用的场景模板
用 cut_in 模板生成一个场景，随机种子设为 42
生成 20 个前车急刹的场景，每个参数在合理范围内随机
校验刚才生成的场景文件

代码示例

from scenario_templates import build
from osc_builder import write_scenario

# 同一个模板 + 不同种子 = 参数区间内的不同场景，结构一致
for seed in range(20):
    spec = build("lead_brake", seed=seed)
    write_scenario(spec, "output/lead_brake_%02d.xosc" % seed)

ScenarioSpec 的核心字段：

字段 说明
entities 实体列表（车辆/行人），含初始位置与速度
behaviors 行为列表（26 类，如变速、变道、跟驰）
triggers 触发列表（10 类，如时间、距离、时距）
fingerprint() 场景指纹，用于批量去重

校验输出示例

✅ 场景校验通过

   实体：4 个（3 车辆 + 1 行人）
   行为：5 个
   触发：4 个

7 种布局与默认参数

布局 含义 默认参数

highway_curve 高速弯道 radius=250, angle=90, lanes=2, spiral_len=40

对话示例

列出所有路网布局
生成一个十字路口路网
生成一个匝道合流路网，主路 4 车道、匝道 2 车道

代码示例

from road_builder import write, inspect_road

write("cross_junction", "output/cross_junction.xodr",
      {"arm_length": 100.0, "lanes": 2})

info = inspect_road("output/cross_junction.xodr")
print(info["valid"], info["road_count"], info["geometry_count"])
# True 12 28

重要：inspect_road() 会检查 <planView/> 是否有几何。生成时必须调用 OpenDrive.adjust_roads_and_lanes()，否则写出的 xodr 没有几何， CARLA 加载会一直等到超时。

3.3 场景与路网进 CARLA

工具参数

run_road_in_carla

参数 类型 默认值 说明
layout string straight 路网布局
params_json string {} 覆盖默认参数
vehicle_count int 5 布景车辆数
capture bool True 是否截图
out_dir string llm/output/carla/shots/<layout> 截图目录
host / port string/int 127.0.0.1 / 2000 CARLA 地址

run_scenario_in_carla

参数 类型 默认值 说明
template string lead_brake 场景模板（与 xosc_path 二选一）
xosc_path string 空 直接指定 .xosc 文件
xodr_layout string straight 承载场景的路网
duration float 0 播放时长；0 表示用场景自身 StopTrigger
capture_times string 2,5 截图时刻，逗号分隔

对话示例

CARLA 连上了吗
把十字路口路网加载进 CARLA 并截图
在 CARLA 里播放 cut_in 场景，第 2 秒和第 5 秒各截一张图
把 wrong_way 场景跑 6 秒看看效果

代码示例

import carla_runner as CR
from scenario_templates import build
from osc_builder import write_scenario
from xosc_player import parse_xosc, play

client = CR.connect()
world = CR.load_xodr_world(client, "output/straight.xodr")
CR.clear_actors(world)

spec = build("cut_in", seed=1)
write_scenario(spec, "output/cut_in.xosc")
sc = parse_xosc("output/cut_in.xosc")

res = play(world, sc, duration=8.0, capture_at=[2.0, 5.0],
           out_dir="output/shots")
print(res["events_fired"], "/", res["events_total"])

播放器支持范围

类型 支持 说明
实体 Vehicle / Pedestrian
初始化 TeleportAction LanePosition / WorldPosition
速度动作 SpeedAction step 与 linear 动力学
跟驰 LongitudinalDistanceAction P 控制维持间距
变道 LaneChangeAction 纯追踪转向控制
横向偏移 LaneOffsetAction
时间触发 SimulationTimeCondition
时距触发 TimeHeadwayCondition 间距 / 自身车速
距离触发 DistanceCondition 到指定位置
速度触发 SpeedCondition
静止触发 StandStillCondition
到达触发 ReachPositionCondition 按 tolerance

不支持（会记入 unsupported 并明确返回，不会静默跳过）： CollisionCondition、TimeToCollisionCondition、RelativeSpeedCondition、 AccelerationCondition、FollowTrajectoryAction、Story 分支、Catalog。

3.4 实采轨迹批量合成

工具参数

synthesize_trajectory_dataset

参数 类型 默认值 说明
seed_path string 必填 种子轨迹文件
n int 100 合成数量
seed int None 随机种子
n_ops int 2 每条轨迹叠加的算子数
strength string mild 增强强度 mild / medium / strong
max_per_seed int None 每个种子的最大衍生数

5 类增强算子

算子 作用
加噪 位置/速度叠加高斯噪声
时间缩放 整体加速或减速
平移 起点位置与航向偏移
法向偏移 沿车道法向横向偏移
速度变形 速度曲线重新塑形

对话示例

导入 _traj_samples 里的轨迹数据
基于这些轨迹合成 100 条数据
对比合成数据和真实数据的分布
把轨迹导出成 SUMO 的需求文件

代码示例

from trajectory_io import load_trajectories
from synthesis_batch import synthesize

seeds = load_trajectories("data/ngsim_sample.csv")
result = synthesize(seeds, n=100, seed=42, n_ops=2, strength="mild")
print(result["generated"], result["skipped"])
# 100 0

单位注意

NGSIM 格式的 Local_X / Local_Y 是英尺，v_Vel 是 ft/s，Global_Time 是毫秒。 导入时会自动推断并换算，同时校验"报告速度 vs 位置差分"， 偏差超过 50% 会告警。

6. 已知限制

6.1 播放器是子集实现

不支持的条件与动作会记入 unsupported 并明确返回。跟驰用 P 控制、 变道用纯追踪，都没做加速度约束；freespace / alongroute 按直线距离处理。

6.2 路口环是折线拼接

CommonJunctionCreator 用直线连接各臂端点，十字路口呈现为菱形环 而不是正方形环。拓扑正确、可通行，但几何不是真实交叉口的样子。

6.3 CARLA 客户端断言

一次进程内连续切换多个世界会偶发 _episode != nullptr 断言（引擎侧问题）。 目前的规避方式是每种布局跑独立进程。

6.4 测试环境

集显 + -quality-level=Low 下完成，未在独立显卡 / 高画质复验。

6.5 轨迹数据

当前没有真实车队数据，测试用符合 NGSIM 格式的合成样本（3 条 / 180 帧 / 10 Hz）。 拿到实采数据后需要重跑分布对比确认增强强度是否合适。
